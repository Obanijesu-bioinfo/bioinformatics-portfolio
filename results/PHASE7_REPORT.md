## 7. ORA methods and results

### 7.1 Method

- Hypergeometric test (clusterProfiler `enrichGO`, `enrichKEGG`, `enrichPathway`).
- Term size 10–500 genes.
- `pvalueCutoff = qvalueCutoff = 1`, so every tested term is saved.
- BH adjustment within each analysis × gene list × database.
- **Significant = BH-adjusted p < 0.05 and Count ≥ 2.**
- Fold enrichment = GeneRatio / BgRatio. GeneRatio's denominator is the number of list genes annotated in that database, not the full list size.

## 8. GSEA methods and results

### 8.1 Method

- clusterProfiler `gseGO` / `gseKEGG` / `gsePathway` with the fgsea backend (`fgseaMultilevel`).
- `eps = 0`, `set.seed(42)` and `seed = TRUE` before each run.
- Set size 10–500; exponent 1.
- BH adjustment within each analysis × database.
- **Significant = BH-adjusted p < 0.05.**
- Ranking: DESeq2 Wald statistic (treatment vs control).
- Leading-edge Entrez IDs converted to gene symbols with org.Hs.eg.db for readability.

## 14. Limitations

1. **What significance means.** A significant term shows statistical over-representation (ORA) or a shift in ranking position (GSEA) relative to this universe. It does not show that a pathway is activated or inhibited, or that the treatment causes it. Pathway names, especially disease-named KEGG maps, describe the database category, not the samples.
2. **Small gene lists and few annotated genes.**
   - C1 primary ORA rests on 10 mapped up genes, of which 2–6 are annotated per database. Both significant terms are 2-gene results.
   - Tests that are not significant on such lists have little power and are not evidence of no effect.
   - Unmapped significant genes (mostly non-coding) are outside all categories.
3. **Redundancy.** GO is hierarchical and Reactome/KEGG pathways overlap. Histone genes alone drive most of the C1 lower-in-treatment and C2 higher-in-treatment Reactome results. MT-encoded and ER-stress genes drive most of the C1_without_A3 ORA results. Counts of significant sets overstate the number of independent signals. BH control is approximate under such dependence.
4. **The histone signal and library preparation.** Most replication-dependent histone mRNAs are not polyadenylated. How strongly they are measured depends on the RNA-seq library protocol (poly(A) selection or rRNA depletion), and Phase 7 did not examine that protocol. The histone-driven results should therefore be checked against the library protocol before being described further. This is a technical caveat, not a biological interpretation.
5. **Mitochondrially encoded genes** (MT-*) are few, highly expressed and handled differently by some pipelines. Their dominance in C1_without_A3 ORA should be read as reflecting a small group of genes.
6. **Gene-length and expression bias.** RNA-seq has more power for long and highly expressed genes. No goseq-type correction was applied, by design. ORA terms rich in such genes may be favoured.
7. **Annotation bias and version gap.** Well-studied genes are annotated more richly. The Ensembl 97 (2019) mapping and current GO/KEGG/Reactome releases differ (Section 5.1). KEGG was queried live and will change.
8. **The A3 sensitivity analysis** has only 2 controls and was defined after inspecting the data. Results present only with A3 (115 GSEA sets, both ORA terms) depend on one sample.
9. **fgsea precision.** One C1 GO_MF set has no p-value, and some very small p-values in four C1 runs may be overestimated (Section 13.1).
10. **Design.** Each comparison is 3 vs 3 samples in one cell line at one time point. C1 and C2 differ in cell line, treatment and vehicle, so they cannot be compared formally.
11. **ORA vs GSEA.** ORA depends on the padj < 0.05 cut-off. GSEA uses all genes but can detect small coordinated shifts of uncertain biological size. Agreement between the methods is more informative than either alone.

## 15. Reproducibility

### 15.1 How to rerun

From the repository root:

```
Rscript data/raw/notebooks/07_functional_enrichment.R
```

- Requires R 4.5.1, Bioconductor 3.22 and the packages in Section 4.
- Requires AnnotationHub access (AH73881, cached after the first download) and internet access for KEGG.
- Takes about 1.5 hours.
- Overwrites `results/tables/phase7_*.csv` and figures 26–35. Writes `results/PHASE7_AUTOGENERATED_SUMMARY.md`. **Cannot overwrite this report.**

To redraw only the running-score figures from the saved tables, without running any enrichment test (a few minutes):

```
Rscript data/raw/notebooks/07b_regenerate_running_score_figures.R
```

### 15.2 Expected reproducibility

- **Deterministic:**
  - ID mapping, universes and rankings;
  - ORA (hypergeometric) for GO and Reactome;
  - GSEA ES, rank and leading edges, given the same package versions and gene sets.
- **Expected to reproduce, but not re-verified:** GSEA NES and p-values. They depend on fgsea's random sampling, which is seeded with `set.seed(42)` before each run (fgsea 1.36.2).
- **Not guaranteed:**
  - KEGG ORA and GSEA, because live KEGG may have changed since 2026-11-24;
  - results under other versions of org.Hs.eg.db, reactome.db, clusterProfiler or fgsea.
- **Not rerun in full during review.** The full script was not rerun after the 2026-11-25 edits; that would be a new analysis run with a new KEGG query.
- **What was checked instead after the edits:**
  - the edited script parses;
  - the new provenance code was executed and returns the values in Section 5.1;
  - the overwrite guard stops when pointed at this report;
  - the figure script reproduces the saved ES, rank and leading edges exactly (9/9).
